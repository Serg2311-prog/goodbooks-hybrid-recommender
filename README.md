# Гибридная рекомендательная система книг (Goodbooks-10k)

Итоговый проект по курсу «Рекомендательные системы». Он развивает домашнюю работу `HW_1_FINAL.ipynb` (Popularity, Content-Based, Item-Based CF, SVD и простой switch-гибрид) до сквозной системы. В неё входят признаки пользователей, книг и взаимодействий, гибрид с весами, подобранными на validation, балансировка популярности и разнообразия, обработка новых, коротких и активных пользователей, а также нейросетевая модель Two-Tower на PyTorch.

`HW_1_FINAL.ipynb` и датасеты не изменяются: проект только читает их. Test-разбиение совпадает с домашней работой, и это проверяется assert-ами.

## Запуск

Команды выполняются из папки `FINAL_PROJECT`. На Windows вместо `python` может понадобиться `py`.

```powershell

python -m jupyter nbconvert --to notebook --execute Final_Project.ipynb --inplace --ExecutePreprocessor.timeout=-1

# быстрая проверка ноутбука на подвыборке (~5 мин); результаты и модели пишутся в fast_check/

python -m recsys.pipeline --fast    # подвыборка, пишет в fast_check/

python -m pytest tests -q

# другой источник данных
```

Seeds фиксированы (`random_state = 42`, `val_random_state = 43`, `torch.manual_seed`, детерминированные алгоритмы PyTorch). Повторный запуск даёт те же числа.

## Логика решения

**Пайплайн:** загрузка → проверки и очистка → разбиение → признаки → обучение → кандидаты → ранжирование → оценка → рекомендации.

**Разбиение.**
* Сохранена схема HW1: per-user holdout 20 % с seed 42. `train_full` (788 503 оценки) и `test` (190 975) совпадают с `train_df` и `test_df` HW1.
* Validation выделяется из `train_full` тем же алгоритмом с seed 43. Получается `train` (639 011) и `val` (149 492).
* Схема двухэтапная:
  1. Все решения принимаются на `train` → `val`: гиперпараметры, веса гибрида, λ MMR, вес популярности, эпоха Two-Tower, стратегия cold start.
  2. Затем модели переобучаются на `train_full` с зафиксированными параметрами и **один раз** оцениваются на `test`.
* Assert-ы проверяют, что пары (user, book) не пересекаются между частями и что `train_full = train + val`. Признаки каждого этапа считаются только по его обучающей части.

**Признаки.**
* Пользователи: активность, средняя оценка и её разброс, доля высоких оценок, сглаженное смещение, «мейнстримность», широта вкуса, сегмент активности, тематический профиль.
* Книги: число оценок, средняя и разброс, доля высоких, weighted rating, перцентиль популярности, год, 20 тематик NMF по тегам, автор, контентный эмбеддинг.
* Взаимодействия: контентная релевантность, CF-сходство с историей, совпадение автора, тематическое соответствие.

Определение каждого признака приведено в разделе 3 ноутбука.

**Гибрид.**
* Каждая модель выдаёт score для всего каталога. Score z-нормализуется по непрочитанным книгам пользователя, прочитанные исключаются.
* Пул кандидатов — объединение top-50 каждого генератора: в среднем ≈ 211 книг на пользователя для всех шести генераторов. Каждый вариант гибрида ранжирует только книги пула от своих генераторов: классические — от пяти классических моделей, варианты +TT — от всех шести.
* Итоговый score — взвешенная сумма. Веса подбираются на validation отдельно для сегментов short (1–5 оценок), medium (6–20) и active (> 20).
* MMR по контентным эмбеддингам повышает разнообразие; λ выбирается на validation с ограничением потери nDCG@10 не более 3 %.
* Новые пользователи получают fallback по популярности.
* Сервисный интерфейс — `HybridRecommender.recommend(user_id, n)`.

**Two-Tower.**
* Башня пользователя: ID-эмбеддинг (ID-dropout, индекс 0 = новый пользователь), признаки и тематический профиль.
* Башня книги: ID, признаки, тематики, эмбеддинг автора.
* Loss — in-batch sampled softmax с температурой, logQ-коррекцией популярности и маскированием совпадений в батче.
* Early stopping по nDCG@10 на validation, лучшая модель сохраняется. Затем модель переобучается на `train_full` на найденное число эпох.

**Оценка.**
* Основной протокол — **full-catalog candidate generation + pooled hybrid ranking** на 10 000 test-пользователях. Гибриды работают в два этапа:
  1. Каждая модель-генератор ранжирует весь каталог непрочитанных книг и отдаёт top-50.
  2. Score всех сигналов для книг объединённого пула смешиваются с весами варианта, при необходимости применяется MMR, и top-K выбирается внутри пула.
* Одиночные модели оцениваются на кандидатах из полного каталога: внутри пула модель ранжирует только собственный top-50, поэтому её top-K совпадает с top-K по всему каталогу. Гибриды весь каталог не ранжируют: книга вне пула в их выдачу не попадает.
* Релевантные test-книги в пул искусственно не добавляются. Precision/Recall/nDCG@K считаются относительно всех фактических test-релевантных книг пользователя, включая не попавшие в пул.
* Метрики: Precision/Recall/nDCG@5 и @10 с порогом релевантности rating ≥ 4, ILD, разнообразие авторов, novelty, покрытие, Gini.
* Дополнительно воспроизведён протокол HW1 (relevant + 100 негативов): Popularity, Item-CF и SVD из HW1 совпадают с его таблицей с точностью до 4e-7.
* Значимость различий проверяется paired bootstrap.

## Результаты (test, full-catalog candidate generation + pooled hybrid ranking, 10 000 пользователей)

| Модель | nDCG@5 | Recall@5 | nDCG@10 | Recall@10 | ILD@10 | Coverage@10 |
|---|---|---|---|---|---|---|
| Popularity | 0.0007 | 0.0009 | 0.0008 | 0.0012 | 0.370 | 0.002 |
| Content-Based | 0.1274 | 0.1380 | 0.1401 | 0.1836 | 0.218 | 0.887 |
| Item-Based CF | 0.1991 | 0.1995 | 0.2123 | 0.2569 | 0.430 | 0.924 |
| SVD (Funk, как в HW1) | 0.0006 | 0.0005 | 0.0009 | 0.0015 | 0.594 | 0.020 |
| SVD (PureSVD) | 0.1169 | 0.1105 | 0.1301 | 0.1657 | 0.316 | 0.686 |
| Two-Tower | 0.1605 | 0.1697 | 0.1746 | 0.2236 | 0.446 | 0.970 |
| Hybrid-Switch (HW1) | 0.0415 | 0.0551 | 0.0465 | 0.0708 | 0.464 | 0.659 |
| Hybrid-Weighted (базовый гибрид) | 0.2022 | 0.2030 | 0.2167 | 0.2647 | 0.363 | 0.941 |
| Hybrid-Improved (сегменты + MMR) | 0.2025 | 0.2031 | 0.2160 | 0.2611 | 0.540 | 0.946 |
| Hybrid-Segment+TT | 0.2081 | 0.2115 | 0.2237 | 0.2758 | 0.353 | 0.931 |
| **Hybrid-Improved+TT (итоговая)** | 0.2084 | 0.2112 | 0.2230 | 0.2732 | 0.527 | 0.947 |

Главные выводы (подробно — в разделе 10 ноутбука):

* Лучшая одиночная модель — Item-Based CF.
* Базовый взвешенный гибрид значимо лучше неё: +0.0044 nDCG@10.
* Признаки взаимодействий и веса по сегментам значимого прироста **не дали**.
* В классическом гибриде MMR повышает ILD@10 с 0.36 до 0.54 без значимой потери nDCG@10 (−0.0004).
* Two-Tower отдельно уступает Item-CF, но внутри гибрида значимо улучшает каждый вариант (+0.006–0.007).
* Итоговая система на +5.0 % выше Item-CF по nDCG@10 (95 % ДИ [+0.008; +0.013]); у коротких историй прирост +8.6 %.
* Максимальный nDCG@10 у Hybrid-Segment+TT (0.2237, ILD@10 = 0.3525), а не у итоговой системы. Итоговой выбрана та же модель с MMR, Hybrid-Improved+TT (0.2230, ILD@10 = 0.5265). Она теряет 0.0007 nDCG@10 (около 0.3 %), но её список примерно в полтора раза разнообразнее. Значимость разницы nDCG@10 для этой пары не проверялась. Прирост ILD@10 значим.
* Popularity и Funk SVD на этих данных работают на уровне случайной выдачи. Причина в том, что у каждой книги в Goodbooks-10k не больше 100 оценок: популярность в train отрицательно коррелирует с test (−0.56). Поэтому качество холодного старта подтвердить не удалось.

## Ограничения

* В данных нет времени оценок, поэтому используется случайный per-user split, а не разбиение по времени.
* Ограничение ≤ 100 оценок на книгу искажает эффекты популярности.
* Recall пула кандидатов на test — 0.575: это верхняя граница Recall для гибридов, книги вне пула в их выдачу не попадают.
* Доверительные интервалы paired bootstrap рассчитаны по пользователям в одном зафиксированном эксперименте, где каждая модель обучена один раз. Они показывают неопределённость оценки разности на данной выборке test-пользователей. Вариативность обучения между независимыми random seeds в них не входит. Для более сильного вывода о стабильности улучшений понадобились бы повторные обучения с разными seeds.
* У Two-Tower in-batch негативы смещены к популярным книгам и могут включать false negatives.
* Основной протокол оценки применяется к выборке из 10 000 test-пользователей, а не ко всем 53 тысячам.
